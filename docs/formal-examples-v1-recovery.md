## Why v1 cannot be imported

The following recovery attempts were completed:

1. **Repository-wide source audit** — no populated formal Example CSV exists under `data/pilot/` or elsewhere in the repository.
2. **Git history audit** — no commit contains a complete 48-example corpus; Example templates were added as header-only scaffolding only.
3. **Previous ChatGPT conversation recovery** — did not expose the raw original example messages.
4. **Raw-original-message recovery attempt** — raw original example messages are **not accessible**.

Additional facts:

- **Templates are header-only** — `data/templates/examples.csv`, `example_translations.csv`, and `entry_examples.csv` contain headers but no formal Pilot rows.
- **Dev seed / mock / test examples are synthetic** — e.g. `supabase/seed.sql`, `src/data/mock/examples.ts`, and validator fixtures use different sentences and must not substitute for formal data.
- **Old handoff preserved only selected revisions and linking decisions** — Section 16 does not contain the complete authoritative Korean + EN/ZH/JA wording for all 48 examples.

**Conclusion:** The complete reviewed 48-example corpus cannot be recovered. Do not attempt further reconstruction of v1. Do not treat partial summaries as a complete authoritative dataset.

## Rules for Formal Examples v2

1. **v2 is a new reviewed dataset** — not a reconstruction presented as v1.
2. **Recovered exact wording may be reused as frozen anchors** — e.g. the four complete four-language examples (#02, #17, #20, #24) and other explicitly recovered text fields.
3. **Missing v1 wording must never be presented as recovered** — if text was not authoritatively recovered, it is lost until newly authored and reviewed.
4. **New example content must undergo a fresh formal content review** — same pre-publication pipeline as other formal Pilot content.
5. **Lexical links must be manually / semantically reviewed** — not created by naive surface matching.
6. **Examples remain pre-publication** until the normal review pipeline is completed (`draft` / `in_review`; not `published` without review).
7. **Synthetic seed / mock / test examples must not be silently promoted into v2** — e.g. `supabase/seed.sql`, `src/data/mock/examples.ts`, validator fixtures.
8. **v2 must receive new stable example `import_key`s** — do not assume v1 keys existed or can be inferred.
9. **Do not overwrite history** by claiming v2 is identical to lost v1.

## Provenance caution

The surviving project handoff states that formal examples were **"mainly `provenance_type=original`"**.

This does **not** prove that every lost v1 row was `original`. Without per-row authoritative sources, that statement cannot be treated as confirmed metadata for all 48 examples.

For v2:

- Assign **per-row provenance** based on the newly reviewed v2 content.
- Do not infer lost v1 provenance from the handoff summary alone.

Allowed `provenance_type` values (from content schema): `original`, `adapted`, `quoted`, `licensed`, `public_domain`, `unknown`.
