# 产品需求文档（Product Requirements）

> 文档版本：1.0  
> 最后更新：2026-08-03  
> 项目：Korean Reference

---

## 1. 产品概述

Korean Reference 是一个面向中、英、日母语韩语学习者的在线查询网站。用户无需注册即可搜索词条、浏览音变规则、查询用言变形、检索汉字词与习语，并通过三语界面与释义对比加深理解。

### 1.1 产品名称

| 界面语言 | 显示名称 |
|----------|----------|
| English | Korean Reference |
| 简体中文 | 韩语参考 |
| 日本語 | 韓国語リファレンス |

项目内部、仓库、代码统一使用 `Korean Reference`。

### 1.2 产品定位

**英文：** A multilingual Korean reference website for sound changes, conjugation, Hanja vocabulary, idioms, and practical examples.

**中文：** 面向中、英、日母语学习者的韩语音变、用言变形、汉字词与习语查询网站。

**日文：** 中国語・英語・日本語話者向けの、韓国語の音変化、用言活用、漢字語、慣用表現を調べられるリファレンスサイト。

### 1.3 参考与反例

**可参考：**

- Naver Dictionary — 搜索效率、词条信息层级
- Wiktionary — 词条结构、词源与多语言组织
- HowToStudyKorean — 规则解释清晰度
- Jisho — 简洁搜索、结果卡片结构

**需避免：**

- 页面过于拥挤、广告式布局
- 大量无关推荐、过多颜色
- 需多次点击才能看到基础释义
- 传统词典式密集排版
- 过度卡通化的语言学习风格

## 2. 用户与权限

### 2.1 目标用户优先级

1. 中文母语者（内容质量基准）
2. 英语母语者
3. 日语母语者

### 2.2 普通用户权限

**可以：**

- 搜索公开词条与规则
- 查看音变、用言变形、汉字词、习语
- 切换界面语言（zh / en / ja）
- 复制查询结果、分享词条页面
- 提交错误反馈

**不可以：**

- 新建、修改、删除正式词条
- 查看未发布（draft）内容
- 查看其他用户反馈
- 进入管理员功能

### 2.3 管理员权限（第一版）

第一版不开发网站内 `/admin` 后台。管理员通过 **Supabase 管理界面**维护内容：

- 添加/修改词条、规则、例句、翻译
- 查看错误反馈
- 修改发布状态（draft / published / archived）

数据库必须通过 RLS（Row Level Security）保护，不能仅依靠隐藏按钮。

## 3. 多语言需求

### 3.1 界面语言

支持：简体中文（zh）、English（en）、日本語（ja）

- **默认语言：英文**
- 根路径 `/` 可跳转或推荐至 `/en`
- 用户手动切换后，偏好保存至 `localStorage`
- 切换控件：下拉菜单，显示语言全称（English / 简体中文 / 日本語），不使用国旗图标
- 桌面端：导航栏右侧；移动端：汉堡菜单内

### 3.2 URL 结构

```text
/en/...
/zh/...
/ja/...
```

切换语言时 URL 必须同步变化，例如：

```text
/en/entries/deutda → /zh/entries/deutda → /ja/entries/deutda
```

Slug 使用稳定拉丁字母形式，不随界面语言变化。

### 3.3 知识内容多语言

界面文本与知识内容**分开维护**。不同语言的释义、解释、例句翻译存于独立字段或关联表，不得混写在同一长文本字段。

**内容缺失处理：**

| 情况 | 行为 |
|------|------|
| 当前语言内容存在 | 显示当前语言 |
| 当前语言缺失，英文存在 | 回退至英文，并显示明确标记 |
| 英文也缺失 | 显示「内容准备中」 |

回退标记示例（英文界面）：

```text
English content shown because this translation is not yet available.
```

**禁止：** 静默回退、未经审核的机器翻译自动展示。

### 3.4 第一版内容语言要求

- 所有核心界面提供三语
- 核心词条、音变规则、用言变形规则**优先保证中文完整**
- 英文、日文尽量同步完成
- 未完成内容保持 `draft`，不得 `published`

## 4. 功能需求

### 4.1 首页

布局顺序：

1. Hero 简短定位语
2. **大型综合搜索框**（第一视觉重点）
3. 四大模块入口卡片（音变 / 用言变形 / 汉字词 / 习语）
4. 示例查询或常用内容
5. 简短网站说明

### 4.2 主导航

固定结构：

```text
首页 | 综合查询 | 音变 | 用言变形 | 汉字词 | 习语 | 关于
```

- 桌面端：顶部导航
- 移动端：汉堡菜单；顶部保留 Logo/站名、搜索入口、菜单按钮
- 不使用底部 Tab、不使用全局左侧 Sidebar

### 4.3 综合查询

**输入：** 韩文词语（支持跨模块）

**结果展示（按数据可用性自动隐藏空白区）：**

- 标准词形、词性、发音、音变结果
- 中/英/日释义
- 汉字来源、用言变形、不规则类型
- 例句及翻译
- 相关词语、相关习语、易混淆词、标签

**词条详情页：**

- 一页长滚动 + 页面内锚点导航（不用 Tab 拆分主要信息）
- 桌面端：侧栏目录（概要 / 发音 / 音变 / 变形 / 汉字 / 例句 / 相关内容）
- 移动端：折叠式顶部目录按钮
- 基础释义、发音、例句默认展开；次要内容可折叠

**搜索建议（Autocomplete）：**

| 规则 | 值 |
|------|-----|
| 韩文/汉字触发 | ≥ 1 字符 |
| 拉丁/中英日释义触发 | ≥ 2 字符 |
| 防抖 | 200–300 ms |
| 最多建议数 | 8 条 |

建议项显示：词条、词性、简短释义、内容类型、汉字或发音。

键盘：上下选择、Enter 确认、Esc 关闭。

**无完全匹配时的结果顺序：**

1. 标准化后完全匹配
2. 已收录变形形式对应的原形
3. 前缀匹配
4. 部分匹配
5. 汉字、中/英/日释义匹配
6. 相似词或建议
7. 空状态引导（检查拼写、搜原形、前往模块、提交反馈）

**跨模块搜索：** 综合查询结果按类型分组（词条 / 音变规则 / 用言变形 / 汉字词 / 习语）。各模块页保留独立搜索与筛选。

**罗马字：** 可显示，数据结构可保留 `romanization` 字段；第一版不作为核心搜索功能。IPA 不在第一版范围。

### 4.4 音变查询

**规则列表：** 平铺列表 + 分类标签筛选（非分类树）

筛选标签示例：连音、鼻音化、流音化、紧音化、送气音化、ㅎ相关变化、音节末辅音、其他。支持按难度或常用程度排序。

**规则详情页：**

- 可视化分步对比（静态步骤卡或箭头流程，无复杂动画）
- 简明文字说明、条件表格
- 例词、例外与注意事项、相关规则

示例分步展示：

```text
국 + 물 → ㄱ + ㅁ → ㅇ + ㅁ → 궁물
```

**两种入口：**

1. 音变模块 → 浏览规则 → 规则详情
2. 词条详情 → 查看触发的音变 → 跳转规则详情

第一版不要求任意韩文句子的完整自动发音分析。

### 4.5 用言变形查询

**交互：** 选词或输入原形 + 选择条件 → 展示结果

支持：

- 输入或搜索选择已收录用言
- 选择目标形式（词尾、时态、礼貌等级、肯定/否定、句型等）

**结果展示：**

- 原形、词干、变形结果
- 静态编号变形步骤
- 使用的规则、是否不规则、注意事项
- 例句及三语解释

不规则用言须明确标记：类型、变化位置、正确结果、与规则用言的区别。

**不在第一版核心范围：** 输入已变形形式反查原形（综合搜索可通过已收录变形找到原形）。

无可靠结果时明确提示「暂未收录」，不生成未经确认的答案。

### 4.6 汉字词查询

**查询：** 韩文或汉字

**结果：**

- 韩文词形、对应汉字、发音、词性
- 中/英/日释义
- 汉字逐字解释（表格：字 | 韩语读音 | 基本意义）
- 常见搭配、例句、同音汉字词、相关词汇、频率/难度标签

**单字反查（第一版基础支持）：** 输入单个汉字，列出已收录的相关韩语汉字词。

**说明：** 汉字信息用于辅助词源理解，不默认与现代中文/日语同形词完全同义。

移动端表格：纵向卡片或可横向滚动表格。

### 4.7 习语查询

**查询：** 搜索 + 主题分类浏览

**初始分类（数据库标签）：**

- 日常会话、感情与态度、人际关系、工作与学习
- 身体相关、动物相关、正式表达、口语表达

**结果：**

- 习语原文、字面意义、实际意义
- 中/英/日解释、使用场景、语体与正式程度
- 例句及翻译、相近表达、易误用说明

**字面 vs 实际意义：** 桌面两栏对比；移动上下排列。须清晰标注 Literal meaning / Actual meaning。

### 4.8 错误反馈

**入口：**

1. 内容页正文底部「报告错误」按钮
2. 页面右侧或右下角轻量反馈按钮（移动端不用遮挡正文的大型 FAB）

**表单字段：**

- 关联内容 ID（自动填充）
- 页面 URL（自动填充）
- 问题类型（发音/音变/变形/汉字/翻译/例句/显示/其他）
- 用户描述

**反馈数据：** 提交时间、处理状态（pending / reviewed / resolved / dismissed）

**提交体验：** 成功 → Toast；失败 → 表单内错误信息。无独立感谢页。

**防 Spam（第一版）：**

- Honeypot 隐藏字段
- 描述 10–1000 字符
- 同一 IP 或匿名标识每分钟最多 1 次
- 服务端验证
- 防重复快速提交

第一版不强制验证码；滥用严重时可加 Turnstile。

**原则：** 反馈写入数据库，不直接覆盖正式内容；用户不可查看处理状态。

## 5. 视觉与 UI 需求

### 5.1 设计风格

- 学术、稳定、清晰、现代
- 适合长时间阅读
- 简约，偏学术，不过分严肃
- 形状不要太死板：中等圆角、适度卡片层次

### 5.2 色彩

**方向：** 暖灰背景 + 深青色点缀

| 角色 | 说明 |
|------|------|
| Primary | 深青色（建议 `#0F766E` / `#115E59`，Demo 可调整） |
| Background | 暖白或浅暖灰 |
| Surface | 白色 |
| Text | 深灰接近黑 |
| Secondary Accent | 低饱和青绿色 |
| Warning/Error | 低饱和红色 |

色彩基于互补色、邻近色、对比色理论组织，但页面中同时出现的主色数量应克制。

**要求：** 颜色定义为设计系统 CSS 变量，不散落硬编码在组件中。

### 5.3 圆角

| 元素 | 值 |
|------|-----|
| 小型控件 | 6–8px |
| 卡片 | 10–12px |
| 大型容器 | 12–16px |

### 5.4 阴影与层次

- 轻微阴影、清晰分隔线、模块左侧色条、标签状态色
- 层级主要依靠间距、字体、分隔线
- 避免「卡片套卡片」、所有区域都套卡片

### 5.5 图标

使用 Lucide 线性图标区分四大模块（音变 / 用言变形 / 汉字词 / 习语）。图标辅助识别，不代替文字标签。第一版不需要大型插画。

### 5.6 字体

| 语言 | 字体 |
|------|------|
| 韩文 | Pretendard（复杂则 Noto Sans KR） |
| 中文 | Noto Sans SC |
| 日文 | Noto Sans JP |
| 英文 | Inter 或系统无衬线 |

通过 Next.js 字体优化加载；失败时回退系统字体。

### 5.7 明暗模式

第一版支持：跟随系统 + 用户手动切换浅色/深色，选择存 localStorage。

**开发优先级：** 先浅色 → 再深色；代码结构预留主题支持；深色不拖延核心功能。

### 5.8 需避免的视觉元素

大面积渐变、霓虹色、高饱和彩虹、卡通人物、过多动画、视差滚动、自动播放、巨大 Hero、大量玻璃拟态、过重阴影、营销式低密度页面、无意义技术展示动画。

### 5.9 响应式

同一套代码适配手机、平板、桌面。重点测试宽度：360 / 390 / 768 / 1024 / 1440 px。

需处理：导航变化、搜索框尺寸、结果排列、语言切换、长文本换行、手机端表格、弹窗与反馈表单、触摸区域、韩/汉/英/日混排。

## 6. 数据与内容需求

### 6.1 数据接入

| 阶段 | 数据源 |
|------|--------|
| Demo | 本地 Mock（JSON / TypeScript） |
| 正式 MVP | Supabase PostgreSQL |

统一 Repository / Service 层；页面不直接依赖 Mock 文件。

### 6.2 标识与 URL

- 数据库主键：UUID
- 对外 URL：可读 Slug（如 `deutda`）
- Slug 规则：拉丁字母、稳定、不随界面语言变化、发布后尽量不修改

### 6.3 发布状态

| 状态 | 含义 |
|------|------|
| `draft` | 草稿，仅管理员可见 |
| `published` | 正式公开 |
| `archived` | 停止公开，保留历史 |

记录字段：`created_at`、`updated_at`、`published_at`

### 6.4 内容来源

项目提供：导入模板、示例 Seed、字段说明、内容填写规范。

正式内容由维护者逐步提供、校对、导入。不得将 AI 生成内容直接作为正式发布内容。

## 7. 非功能需求

### 7.1 SEO

- Sitemap、robots.txt
- 每页 Title、Description
- Open Graph 基础信息（第一版统一默认 OG 图）
- 各语言 hreflang、canonical URL
- 语义化 HTML、可索引词条详情页

### 7.2 Analytics

第一版使用 Vercel Analytics。不收集不必要个人信息，不做用户画像。

### 7.3 无障碍

目标：WCAG 2.1 AA 基础合规

- 键盘可操作、清晰焦点
- 合理色彩对比、表单 Label
- 图标有文字或 aria-label
- 不仅靠颜色表达信息
- 正确标题层级、语义 HTML
- 动画支持 `prefers-reduced-motion`
- 搜索建议可键盘操作

### 7.4 性能目标

| 指标 | 目标 |
|------|------|
| Lighthouse Performance（桌面） | ≥ 90 |
| Lighthouse Accessibility | ≥ 90 |
| Lighthouse Best Practices | ≥ 90 |
| Lighthouse SEO | ≥ 90 |
| LCP | ≤ 2.5s |
| CLS | ≤ 0.1 |

主要优化：服务端读取、缓存公开词条、字体优化、搜索防抖、合理分页、避免一次加载全部数据。

## 8. 第一版范围边界

详见 [01-soft-overview.md](./01-soft-overview.md) 第一版不包含列表。

**额外开发原则：**

1. 不接入 AI 功能
2. 普通用户不需要注册登录
3. 普通用户不能修改正式内容
4. 管理员第一版通过 Supabase 后台维护
5. 不开发网站内管理员后台
6. 页面、规则逻辑、数据库访问、翻译内容必须分层
7. 所有正式内容必须支持审核状态
8. 数据库权限通过 RLS 保护
9. Demo 允许 Mock，正式 MVP 必须 Supabase
10. 先打通 Cursor → GitHub → Vercel 最小部署链路
11. 接入正式数据库前用少量测试数据验证连接
12. 每阶段完成后更新 [07-current-status.md](./07-current-status.md)
13. 每稳定阶段建立 Git Commit
14. 不得提交真实密钥或 `.env.local`
15. 不未经确认扩展第一版范围
16. 不一次生成整个网站，按 [06-development-plan.md](./06-development-plan.md) 逐阶段验收
17. 数据库结构通过 Migration 文件记录
18. 无法确认正确性的语言内容必须保持 `draft`
